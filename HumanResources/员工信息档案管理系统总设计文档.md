# 员工信息档案管理系统

## 项目总览

基于企业人力资源档案管理痛点，采用 **Vue3 + Node.js + SQLite** 全栈技术栈，构建一体化员工档案管理系统。实现员工信息集中管理、合同到期多级预警、入职周年自动提醒、花名册自定义导出、组织架构可视化等核心能力。

# 员工信息档案管理系统 PRD

## 1. 产品概述

### 1.1 产品背景

企业人力资源部门当前员工信息分散在 Excel 表格与纸质档案中，存在信息更新不同步、合同到期遗漏、人事关怀节点无法自动识别、部门调整信息滞后、花名册导出格式不统一等核心痛点。

### 1.2 产品目标

- 建立统一的员工电子档案库，实现信息一处更新、全局同步
- 自动化合同到期预警，降低用工合规风险
- 自动识别入职周年与生日节点，提升员工归属感
- 支持灵活的花名册导出，适配多部门报送需求
- 可视化组织架构，支撑人员盘点与跨部门协作

### 1.3 目标用户

- 人力资源专员：日常档案维护、合同管理、报表导出
- 部门负责人：查看本部门人员信息、组织架构
- 行政人员：员工关怀提醒、生日 / 周年祝福推送

## 2. 功能需求

### 2.1 员工档案管理

**功能描述**：员工全量信息的增删改查与集中维护

**功能点**：

- 员工基本信息：姓名、工号、性别、部门、岗位、入职日期、身份证号
- 联系方式：手机号、邮箱、紧急联系人、居住地址
- 合同信息：合同类型（固定期限 / 无固定期限 / 试用期）、起止日期、续签次数
- 履历信息：教育背景（学历 / 院校 / 专业 / 毕业时间）、工作经历、项目经历
- 支持单条新增、批量导入、编辑修改、逻辑删除
- 支持按姓名 / 工号模糊搜索，按部门 / 岗位 / 入职状态筛选
- 支持按入职日期、合同到期日排序

### 2.2 合同到期提醒

**功能描述**：多级预警机制，提前识别合同到期风险

**功能点**：

- 支持配置提醒规则：提前 30 天、15 天、7 天三级预警
- 提醒中心集中展示即将到期员工列表，按紧急程度标色
- 支持标记 "已处理" 状态，记录续签结果
- 到期合同自动统计，生成月度续签计划表

### 2.3 入职周年与生日提醒

**功能描述**：自动识别人事关怀节点，提供祝福模板

**功能点**：

- 自动计算本月 / 本周入职周年员工（1 周年、3 周年、5 周年等关键节点高亮）
- 生日提醒：基于身份证号自动提取生日，按月展示
- 内置祝福文案模板，支持一键复制
- 支持按部门筛选关怀名单

### 2.4 花名册导出

**功能描述**：多格式、自定义字段导出

**功能点**：

- 支持导出格式：Excel（.xlsx）、PDF
- 支持自定义导出字段，可保存常用导出模板
- 支持按筛选结果导出、按全量导出
- 导出文件名自动生成规则：花名册_YYYYMMDD_部门

### 2.5 组织架构可视化

**功能描述**：部门人员分布图表展示

**功能点**：

- 各部门人数统计柱状图
- 岗位层级分布饼图
- 司龄分布统计
- 支持下钻查看部门人员明细

### 2.6 员工变动历史

**功能描述**：全流程人事异动记录追溯

**功能点**：

- 记录入职、转岗、调薪、离职等全生命周期变动
- 每次变动记录操作人、操作时间、变更前后对比
- 支持按员工维度查看个人变动轨迹
- 支持按时间维度查看全员变动汇总

## 3. 业务流程

### 3.1 员工入职流程

1. HR 在系统中新增员工档案，填写基本信息、合同信息
2. 系统自动生成工号，创建员工档案
3. 自动计算合同到期日，纳入提醒池
4. 组织架构数据自动更新

### 3.2 合同续签流程

1. 系统提前 30 天发出一级预警
2. HR 确认续签意向，标记处理状态
3. 提前 15 天、7 天持续提醒未处理项
4. 续签完成后更新合同信息，自动生成下一期提醒
5. 变动历史自动记录本次续签操作

### 3.3 花名册导出流程

1. 用户设置筛选条件（部门 / 岗位 / 在职状态等）
2. 选择导出格式与字段
3. 预览导出字段
4. 生成文件并下载

## 4. 非功能需求

### 4.1 性能需求

- 单页列表加载时间 < 2 秒（1000 条数据量）
- 导出 1000 条员工 Excel < 5 秒
- 支持并发用户数 ≥ 20 人

### 4.2 数据安全

- 敏感字段（身份证号、手机号）脱敏展示
- 操作日志留痕，关键操作可追溯
- 数据定期备份机制

### 4.3 易用性

- 列表页支持快捷编辑，减少页面跳转
- 常用操作一键可达
- 导入支持模板下载与错误提示

## 5. 用户场景

### 场景一：新员工入职

HR 专员收到入职审批单，进入系统新增员工档案，填写基本信息、合同起止日期、紧急联系人等信息。系统自动校验工号唯一性，保存后自动纳入合同到期提醒池。

### 场景二：合同到期预警

周一早晨 HR 打开系统，提醒中心展示本月即将到期的 12 名员工，其中 3 人距离到期不足 7 天标红高亮。HR 逐个联系部门负责人确认续签意向，标记处理状态。

### 场景三：月度花名册报送

每月 5 号行政部需要向财务部提交当月在职人员名单。HR 进入员工列表，筛选 "在职" 状态，选择 "姓名、工号、部门、岗位、入职日期" 字段，一键导出 Excel 报送。

### 场景四：员工周年关怀

每月初 HR 查看当月入职周年名单，筛选出满 3 周年、5 周年的员工，复制系统内置祝福模板，配合礼品发放通知各部门负责人。

## 1. 系统架构设计

### 1.1 整体架构

采用前后端分离的 B/S 架构，前端负责页面交互与数据展示，后端提供 RESTful API 接口与业务逻辑处理，SQLite 作为轻量级关系型数据库存储业务数据。

plaintext

```
│   前端 Web 层   │  Vue3 + Element Plus + ECharts
└────────┬────────┘
         │ HTTP/REST API
┌────────▼────────┐
│   后端服务层    │  Node.js + Express
└────────┬────────┘
         │
┌────────▼────────┐
│   数据存储层    │  SQLite3
└─────────────────┘
```

### 1.2 部署架构

单节点部署，前后端同机部署，Nginx 作为反向代理。适合中小企业 100-2000 人规模使用。

## 5. 核心业务逻辑

### 5.1 合同到期预警算法

plaintext







```
1. 查询所有在职员工的当前有效合同
2. 计算 end_date - 当前日期 = 剩余天数
3. 匹配提醒规则：
   - 剩余天数 ≤ 7  → 红色高危
   - 剩余天数 ≤ 15 → 橙色预警
   - 剩余天数 ≤ 30 → 黄色提示
4. 按剩余天数升序排列输出
```

### 5.2 入职周年计算

plaintext







```
1. 提取入职日期的月日部分 entry_month_day
2. 提取当前日期的月日部分 current_month_day
3. 计算周年数 = 当前年份 - 入职年份
4. 若本月内周年日未过，周年数减1
5. 筛选本月/本周周年员工
```

### 5.3 身份证号提取生日

18 位身份证号第 7-14 位为出生日期（YYYYMMDD），系统自动解析并用于生日提醒。

## 6. 安全设计

### 6.1 数据脱敏

- 手机号：中间 4 位打码 138****1234
- 身份证号：只显示前 6 后 4
- 列表页默认脱敏，详情页有权限控制

### 6.2 参数校验

- 后端统一参数校验中间件
- 工号、手机号、邮箱格式校验
- SQL 注入防护：参数化查询

### 6.3 操作日志

所有增删改操作写入变动历史表，记录操作人与时间。

```
    const { page = 1, pageSize = 20, keyword = '', department = '', status = 1, sortField = 'entry_date', sortOrder = 'desc' } = req.query;

    let whereSql = 'WHERE status = ?';
    let params = [status];

        params.push(`%${keyword}%`, `%${keyword}%`);
    }
    if (department) {

        params.push(department);
    }

    const offset = (page - 1) * pageSize;

    const countSql = `SELECT COUNT(*) as total FROM employees ${whereSql}`;
    const listSql = `SELECT * FROM employees ${whereSql} ORDER BY ${sortField} ${sortOrder} LIMIT ? OFFSET ?`;

    db.get(countSql, params, (err, countResult) => {
        if (err) return res.status(500).json({ code: 500, message: err.message });

        db.all(listSql, [...params, Number(pageSize), offset], (err, list) => {

                }

router.get('/:id', (req, res) => {
    const { id } = req.params;
    const db = req.db;

    db.get(sql, [id], (err, employee) => {
        if (err) return res.status(500).json({ code: 500, message: err.message });
        if (!employee) return res.status(404).json({ code: 404, message: '员工不存在' });

        // 并行查询合同、教育、工作履历
        db.all('SELECT * FROM contracts WHERE employee_id = ? ORDER BY start_date DESC', [id], (err, contracts) => {

                db.all('SELECT * FROM work_experience WHERE employee_id = ? ORDER BY start_date DESC', [id], (err, workExp) => {
                    res.json({
                        code: 0,
                        data: {
                            employee,
                            contracts,
                            education,
                            workExperience: workExp
                        }
                    });
                });
            });

        const updatable = ['name', 'gender', 'department', 'position', 'id_card', 'phone', 'email', 'entry_date', 'status', 'emergency_contact', 'emergency_phone', 'address'];
        const updates = [];
        const values = [];

        updatable.forEach(field => {
            if (data[field] !== undefined) {
                updates.push(`${field} = ?`);
                values.push(data[field]);
            }
        });

        if (updates.length === 0) {
            return res.json({ code: 0, message: '无更新内容' });
        }

        values.push(id);
        const sql = `UPDATE employees SET ${updates.join(', ')}, updated_at = CURRENT_TIMESTAMP WHERE id = ?`;

        db.run(sql, values, function (err) {
            if (err) return res.status(500).json({ code: 500, message: err.message });

            // 记录变动历史 - 对比变更字段
            const changes = {};
            updatable.forEach(f => {
                if (data[f] !== undefined && data[f] !== before[f]) {
                    changes[f] = { before: before[f], after: data[f] };
                }
            });

            let changeType = '信息变更';
            if (data.department && data.department !== before.department) {
                changeType = '转岗';
            }
            if (data.status === 2 && before.status === 1) {
                changeType = '离职';
            }

            db.run(
                'INSERT INTO change_history (employee_id, change_type, before_value, after_value, remark) VALUES (?, ?, ?, ?, ?)',
                [id, changeType, JSON.stringify(before), JSON.stringify(data), JSON.stringify(changes)]
```
