# 员工信息档案管理系统 - 技术方案

## 1. 系统架构设计

### 1.1 整体架构

采用前后端分离的 B/S 架构，前端负责页面交互与数据展示，后端提供 RESTful API 接口与业务逻辑处理，SQLite 作为轻量级关系型数据库存储业务数据。

```
┌─────────────────┐
│   前端 Web 层   │  Vue3 + Element Plus + ECharts
└────────┬────────┘
         │ HTTP/REST API
┌────────▼────────┐
│   后端服务层    │  Node.js + Express
└────────┬────────┘
         │
┌────────▼────────┐
│   数据存储层    │  SQLite3
└─────────────────┘
```

### 1.2 部署架构

单节点部署，前后端同机部署，Nginx 作为反向代理。适合中小企业 100-2000 人规模使用。

## 5. 核心业务逻辑

### 5.1 合同到期预警算法

```
1. 查询所有在职员工的当前有效合同
2. 计算 end_date - 当前日期 = 剩余天数
3. 匹配提醒规则：
   - 剩余天数 ≤ 7  → 红色高危
   - 剩余天数 ≤ 15 → 橙色预警
   - 剩余天数 ≤ 30 → 黄色提示
4. 按剩余天数升序排列输出
```

### 5.2 入职周年计算

```
1. 提取入职日期的月日部分 entry_month_day
2. 提取当前日期的月日部分 current_month_day
3. 计算周年数 = 当前年份 - 入职年份
4. 若本月内周年日未过，周年数减 1
5. 筛选本月/本周周年员工
```

### 5.3 身份证号提取生日

18 位身份证号第 7-14 位为出生日期（YYYYMMDD），15 位旧身份证第 7-12 位为出生日期（YYMMDD，默认 19 世纪），系统自动解析并用于生日提醒。

## 6. 安全设计

### 6.1 数据脱敏

- 手机号：中间 4 位打码 138****1234。
- 身份证号：只显示前 6 后 4。
- 列表页默认脱敏，详情页显示完整信息。

### 6.2 参数校验

- 后端统一参数校验中间件。
- 工号、手机号、邮箱、身份证格式校验。
- SQL 注入防护：参数化查询。

### 6.3 操作日志

所有增删改操作写入变动历史表，记录操作人与时间。

## 9. 注意事项

- 本项目使用 Node.js 内置模块 `node:sqlite` 操作 SQLite3 数据库，要求 Node.js 版本 ≥ 22.5.0。该方案无需额外安装 sqlite3 原生依赖，可避免 node-gyp 编译环境问题。
- PDF 导出使用 pdfmake 服务端生成。由于中文字体需要额外字体文件支持，若需完整中文渲染，请将中文字体（如 SimHei.ttf）放置于 `server/fonts/` 目录；否则英文与数字可正常显示，中文会呈现为占位方块。
- 生产环境建议将 SQLite 数据库文件定期备份，并迁移至 MySQL / PostgreSQL 以支撑更高并发。
