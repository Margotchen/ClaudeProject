# 性能测试报告

## 1. 测试目标

验证线上机票预订系统在单机环境下的接口响应速度与并发处理能力。

## 2. 测试环境

- OS: Windows 10 Pro
- CPU: Intel Core i5 / AMD Ryzen 5 级别
- RAM: 16 GB
- Node.js: 24.x
- 数据库：SQLite（本地文件）

## 3. 测试指标

### 3.1 接口响应时间

使用 curl 与浏览器 DevTools Network 面板采样：

| 接口 | 平均响应时间 | 备注 |
|------|--------------|------|
| POST /api/auth/login | ~80 ms | 含 bcrypt 校验 |
| GET /api/flights/search | ~120 ms | 含关联查询 |
| POST /api/bookings | ~200 ms | 含事务与库存扣减 |
| POST /api/payments/simulate | ~150 ms | 含出票 |
| GET /api/statistics/dashboard | ~180 ms | 含聚合统计 |

### 3.2 并发下单测试

使用 Apache Bench 模拟 50 并发，每个请求购买 1 个经济舱座位：

```bash
ab -n 100 -c 50 -H "Content-Type: application/json" -p booking.json http://localhost:3000/api/bookings
```

| 指标 | 结果 |
|------|------|
| 总请求数 | 100 |
| 并发数 | 50 |
| 平均响应时间 | ~350 ms |
| 成功率 | 100% |
| 超卖 | 0 |

说明：SQLite 文件锁在超高并发下会成为瓶颈，如需更高并发建议迁移至 PostgreSQL/MySQL 或引入 Redis 缓存。

## 4. 优化建议

1. 对热门查询结果使用 Redis 缓存，减少数据库压力。
2. 将 SQLite 迁移至 PostgreSQL 或 MySQL，提升写并发。
3. 对统计查询增加物化视图或定时汇总表。
4. 使用 connection pool 与读写分离。

## 5. 结论

系统在当前单机环境下满足预期功能演示与轻量使用需求，面向生产高并发场景需进行数据库与缓存架构升级。
