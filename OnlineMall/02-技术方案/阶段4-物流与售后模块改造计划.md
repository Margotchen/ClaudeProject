# 阶段 4：物流与售后模块改造计划

> **面向 AI 代理的工作者：** 本阶段改造发货登记逻辑，扩展物流轨迹模拟，并实现退款/退货两种售后类型与订单状态联动。

**目标：** 商家可填写物流信息并发货；用户可查看物流轨迹；用户可发起退款/退货售后，商家审核后订单状态联动。

**架构：** 复用 `oms_order` 物流字段，新增售后相关字段与图片表；售后状态变更通过 Service 层同步更新订单状态。

**技术栈：** Spring Boot + MyBatis + MySQL。

### 步骤 3：实现发货逻辑

```java
@Override
public int delivery(List<OmsDeliveryParam> deliveryParamList) {
    int count = 0;
    for (OmsDeliveryParam param : deliveryParamList) {
        OmsOrder order = orderMapper.selectByPrimaryKey(param.getOrderId());
        if (order == null) continue;
        // 校验状态：待发货才能发货
        if (order.getStatus() != OrderStatusEnum.PENDING_SHIP.getValue()) {
            Asserts.fail("订单 " + order.getOrderSn() + " 不是待发货状态");
        }
        OmsOrder update = new OmsOrder();
        update.setId(param.getOrderId());
        update.setDeliveryCompany(param.getDeliveryCompany());
        update.setDeliverySn(param.getDeliverySn());
        update.setDeliveryTime(new Date());
        update.setStatus(OrderStatusEnum.SHIPPED.getValue());
        orderMapper.updateByPrimaryKeySelective(update);

        // 插入模拟物流轨迹
        insertLogisticsTrace(param.getOrderId(), "商家已发货，物流公司：" + param.getDeliveryCompany() + "，运单号：" + param.getDeliverySn());
        count++;
    }
    return count;
}
```

### 步骤 4：改造商家审核接口

新建 DTO：

```java
@Data
public class OmsReturnApplyHandleParam {
    @NotNull
    private Long applyId;
    @NotNull
    private Integer status; // 1-通过 2-驳回
    private String handleRemark;
}
```

审核逻辑：
- 通过：售后完结，订单状态根据售后类型流转
  - 退款 → 订单状态变为 6（已取消）
  - 退货 → 订单状态变为 5（已完成）
- 驳回：售后完结，订单状态恢复为售后前状态（需记录售后前状态）
