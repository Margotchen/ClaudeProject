# 在线商城订单管理系统 - 各模块实现计划总览

> **面向 AI 代理的工作者：** 本计划按模块拆分为 6 个阶段，每个阶段独立可执行、可验证。建议按顺序推进，阶段 2 完成后可为后续所有阶段提供商家数据权限基础。

**目标：** 基于 `macrozheng/mall` 完成在线商城订单管理系统的需求改造，覆盖商家角色、数据权限、订单状态机、支付超时、物流售后、统计报表及前端适配。

**架构：** 后端在 `mall-admin` 模块中扩展商家模型、数据权限过滤、状态机与定时任务；前端在 `mall-admin-web` 中扩展商家菜单、页面与权限路由。

**技术栈：** Spring Boot 3.5 + MyBatis-Plus + MySQL 8.0 + Vue3 + Element Plus + JWT。

## 跨阶段公共约定

### 文件路径约定

- 后端主模块：`05-项目源代码/backend/mall-admin/`
- 前端主模块：`05-项目源代码/frontend/`
- SQL 文件统一放在：`05-项目源代码/backend/document/sql/mall-upgrade.sql`
- 后端新增 Java 文件优先放在 `mall-admin` 对应包下
- 后端改造文件优先遵循原 `mall` 的分层：`controller` / `service` / `service/impl` / `dao` / `dto` / `bo`

### 数据权限约定

- 所有商家相关表增加 `shop_id` 字段
- 平台管理员 `shop_id = null`，可查看全部数据
- 商家账号 `shop_id = 其所属商家 ID`，查询时自动附加 `shop_id = ?` 条件
- 数据权限在 MyBatis Mapper XML 或 Service 层统一拦截

### 状态机约定

系统统一 8 种订单状态：

```
0: 待支付
1: 已支付
2: 待发货
3: 已发货
4: 已收货
5: 已完成
6: 已取消
7: 售后中
```

合法流转矩阵在阶段 3 详细计划中定义。

### 测试约定

- 每阶段完成后更新 `03-测试报告/功能测试报告.md`
- 关键接口用 `curl` 或 Postman 验证
- 每阶段提交一次，commit message 格式：`feat: 阶段X - 简要描述`
