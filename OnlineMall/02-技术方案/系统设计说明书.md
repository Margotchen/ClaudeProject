# 在线商城订单管理系统 - 系统设计说明书

## 1. 项目概述

基于 `macrozheng/mall` 开源电商系统改造，实现覆盖商品、购物车、订单、支付、物流、售后、权限、统计报表的完整在线商城订单管理系统。

- **核心目标**：实现订单全生命周期线上化管理，支持用户/商家/管理员三角色数据隔离。
- **架构风格**：前后端分离，RESTful API 通信，JWT Token 鉴权。

## 2. 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | Vue3 + Element Plus | 管理后台（mall-admin-web） |
| 后端 | Spring Boot + MyBatis-Plus | 业务逻辑与数据服务（macrozheng/mall） |
| 数据库 | MySQL 8.0 | 关系型数据存储 |
| 缓存 | Redis | 会话、热点数据缓存（可选，优先复用 mall 配置） |
| 消息队列 | RabbitMQ | 异步通知、延迟消息（可选） |
| 搜索 | Elasticsearch | 商品搜索（可选） |
| 鉴权 | JWT Token | 登录后签发 Token，请求头携带 |

## 4. 角色与权限设计

| 角色 | 数据范围 | 核心权限 |
|------|----------|----------|
| 普通用户 | 仅自身数据 | 浏览商品、购物车、下单、查看物流、发起售后 |
| 商家 | 自身店铺数据 | 商品管理、订单处理、发货登记、售后审核 |
| 平台管理员 | 全平台数据 | 订单全局查询、经营统计、报表导出、系统配置 |

**实现方式**：在 `mall` 原有 `ums_admin` 和 `ums_role` 基础上，新增 `MERCHANT` 角色和 `ums_merchant` 商家表。所有商家相关查询通过 `shop_id` 过滤。

## 5. 核心数据模型

### 5.1 新增表

- `ums_merchant`：商家信息（商家 ID、店铺名称、状态、联系人等）
- `ums_admin` 增加 `merchant_id`：关联商家
- `pms_product` 增加 `shop_id`：商品归属店铺
- `oms_order` 增加 `shop_id`：订单归属店铺

### 5.2 复用表

- 用户：`ums_member`
- 商品分类：`pms_product_category`
- 商品：`pms_product`
- SKU：`pms_sku_stock`
- 购物车：`oms_cart_item`
- 订单：`oms_order`
- 订单明细：`oms_order_item`
- 物流：`oms_company_address` / `oms_order` 物流字段
- 售后：基于 `oms_order_return_apply` 扩展
- 支付流水：`oms_order` 支付信息 + 扩展支付流水表

## 6. 订单状态机

```
待支付
  │ 支付成功
  ▼
已支付 ──→ 待发货 ──→ 已发货 ──→ 已收货 ──→ 已完成
  │           │
  │ 支付超时   │ 用户取消
  ▼           ▼
已取消      售后中 ──→ 退款完成 / 退货完成 / 售后驳回
```

状态流转规则：
- 待支付 → 已支付（支付成功）
- 待支付 → 已取消（用户取消或超时）
- 已支付 → 待发货（系统自动）
- 待发货 → 已发货（商家发货）
- 已发货 → 已收货（用户确认）
- 已收货 → 已完成（售后期结束或无售后）
- 已支付/待发货/已发货 → 售后中（用户发起售后）
- 售后中 → 已完成 / 已取消（售后完结）

## 7. 模块实现策略

### 7.1 商品与购物车
- 复用 `mall` 原有商品、SKU、分类、购物车模块。
- 商家发布商品时自动写入当前商家 `shop_id`。
- 商家查询商品时加 `shop_id = 当前商家` 过滤。

### 7.2 订单管理
- 复用订单创建、库存扣减逻辑。
- 改造订单状态枚举，对齐 8 种状态。
- 商家只能查看和处理自己店铺的订单。

### 7.3 支付模块
- 复用 `mall` 模拟支付接口。
- 增加支付超时定时任务，扫描 `待支付` 订单，超时后自动取消并释放库存。

### 7.4 物流模块
- 复用发货逻辑。
- 用户端查看物流公司、运单号、模拟物流轨迹。

### 7.5 售后模块
- 在 `oms_order_return_apply` 基础上扩展：售后类型（退款/退货）、凭证图片、商家审核意见。
- 售后状态变更时同步更新订单状态为「售后中」或对应终态。

### 7.6 统计报表
- 复用 `mall` 销售统计接口。
- 扩展商品维度统计（销量、销售额、退款率）和类目维度统计（销售占比、订单分布）。
- 支持 Excel/CSV 导出。

## 8. 接口规范

- 统一返回格式：`{ code: 200, message: "", data: {} }`
- 鉴权头：`Authorization: Bearer {token}`
- HTTP 方法：GET 查询、POST 创建、PUT 更新、DELETE 删除
- 错误码：按 mall 原有错误码体系扩展

## 9. 安全设计

- 密码使用 BCrypt 加密存储。
- JWT Token 设置合理过期时间。
- 接口按角色鉴权，商家操作校验 `shop_id` 归属。
- 敏感字段脱敏展示（手机号、地址等）。

## 10. 部署方案

### 10.1 本地开发环境启动

本地开发采用手动启动方式：先启动 MySQL 数据库并导入初始化 SQL，再启动后端 `mall-admin` 服务，最后启动前端 Vite 开发服务器。

#### 10.1.1 环境准备

确认以下组件已安装并可用（路径以当前开发机为准）：

| 组件 | 版本 | 本机路径（示例） |
|------|------|------------------|
| JDK | 17 | `C:\jdk-17-temp` |
| Maven | 3.9.16 | `C:\apache-maven-3.9.16` |
| MySQL | 8.0.39 | `C:\mysql-8.0.39` |
| Node.js | 24.x | 已加入系统 PATH |

若 `java`、`mvn` 未加入系统 PATH，启动后端前需要先设置环境变量：

```bash
export JAVA_HOME="/c/jdk-17-temp"
export PATH="/c/jdk-17-temp/bin:/c/apache-maven-3.9.16/bin:$PATH"
```

#### 10.1.2 启动 MySQL 数据库

1. 进入 MySQL 安装目录并启动服务：

```bash
cd C:/mysql-8.0.39
mysqld --console
```

2. 使用 MySQL 客户端连接并创建数据库：

```bash
mysql -u root -p
```

```sql
CREATE DATABASE IF NOT EXISTS mall DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

3. 导入项目初始化 SQL 与升级脚本：

```bash
mysql -u root -p mall < 05-项目源代码/backend/document/sql/mall.sql
mysql -u root -p mall < 05-项目源代码/backend/document/sql/mall-upgrade.sql
```

> 说明：若 `mall.sql` 中已包含 `mall-upgrade.sql` 的升级内容，则只需导入最新脚本即可。当前项目以 `mall-upgrade.sql` 作为阶段性升级入口。

#### 10.1.3 启动后端服务

1. 进入后端 `mall-admin` 模块：

```bash
cd 05-项目源代码/backend/mall-admin
```

2. 启动 `mall-admin` 服务：

```bash
mvn spring-boot:run
```

> 说明：后端默认使用 `application-dev.yml` 配置文件，请确认其中 MySQL 连接地址、用户名、密码与本地环境一致。Redis、RabbitMQ、MinIO、Elasticsearch 等组件当前为可选依赖，未部署时部分功能（如缓存、消息、文件上传）可能降级或不可用。

**MySQL 8 连接注意事项**

MySQL 8 默认使用 `caching_sha2_password` 认证插件，直接连接可能出现 `Public Key Retrieval is not allowed` 错误。当前项目已在 `application-dev.yml` 的 JDBC URL 中追加 `allowPublicKeyRetrieval=true` 参数解决：

```yaml
url: jdbc:mysql://localhost:3306/mall?useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
```

后端服务启动后访问地址：

- 服务根地址：`http://localhost:8080`
- Swagger 文档：`http://localhost:8080/swagger-ui/index.html`

#### 10.1.4 启动前端服务

1. 进入前端项目目录：

```bash
cd 05-项目源代码/frontend
```

2. 安装依赖（首次启动使用）：

```bash
npm install
```

3. 启动 Vite 开发服务器：

```bash
npm run dev
```

前端服务启动后访问地址：

- 管理后台：`http://localhost:5173`（实际端口以 Vite 控制台输出为准）
