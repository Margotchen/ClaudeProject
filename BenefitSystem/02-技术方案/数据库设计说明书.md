# 企业福利礼品申领管理系统 - 数据库设计说明书

## 1. 数据库选型

本系统采用 SQLite 作为关系型数据库，单文件部署，适合中小型企业内部系统。开发及测试阶段通过 `better-sqlite3` + Sequelize ORM 访问，生产环境可直接使用 SQL 脚本初始化。

## 2. ER 关系

```
sys_role ||--o{ sys_user : has
sys_user ||--o{ user_address : owns
sys_user ||--o{ welfare_apply : submits
welfare_activity ||--o{ welfare_apply : contains
welfare_activity ||--o{ activity_gift_rel : includes
gift_info ||--o{ activity_gift_rel : included_by
welfare_apply ||--o{ welfare_apply_item : has
gift_info ||--o{ welfare_apply_item : references
```

## 3. 表结构

### 3.1 sys_role（系统角色表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INTEGER | PK, AUTOINCREMENT | 角色 ID |
| role_code | VARCHAR(32) | UNIQUE, NOT NULL | 角色编码：employee/hr/admin |
| role_name | VARCHAR(64) | NOT NULL | 角色名称 |
| description | VARCHAR(255) | | 角色描述 |
| create_time | DATETIME | DEFAULT CURRENT_TIMESTAMP | 创建时间 |

初始数据：
- `employee`：普通员工
- `hr`：HR 管理员
- `admin`：系统管理员

## 4. 索引设计

```sql
CREATE INDEX idx_apply_activity_user ON welfare_apply(activity_id, user_id);
CREATE INDEX idx_apply_item_apply ON welfare_apply_item(apply_id);
CREATE INDEX idx_apply_item_gift ON welfare_apply_item(apply_id, gift_id);
CREATE INDEX idx_address_user_default ON user_address(user_id, is_default);
CREATE INDEX idx_gift_status_stock ON gift_info(status, stock);
CREATE INDEX idx_activity_time_status ON welfare_activity(start_time, end_time, status);
```

## 5. 关联关系

| 主表 | 从表 | 关联字段 | 关系类型 |
|------|------|----------|----------|
| sys_role | sys_user | role_id | 一对多 |
| sys_user | user_address | user_id | 一对多 |
| sys_user | welfare_apply | user_id | 一对多 |
| welfare_activity | welfare_apply | activity_id | 一对多 |
| welfare_activity | activity_gift_rel | activity_id | 多对多（通过关联表） |
| gift_info | activity_gift_rel | gift_id | 多对多（通过关联表） |
| welfare_apply | welfare_apply_item | apply_id | 一对多 |
| gift_info | welfare_apply_item | gift_id | 一对多 |

## 7. 数据安全

- 用户密码使用 `bcryptjs` 进行单向哈希存储，盐轮数 10。
- JWT Secret 通过环境变量配置，避免硬编码。
- 数据库文件建议定期备份，敏感生产环境应限制文件访问权限。
