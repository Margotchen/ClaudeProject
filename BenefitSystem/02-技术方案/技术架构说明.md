# 企业福利礼品申领管理系统 - 技术架构说明

## 1. 项目概述

本系统为企业内部福利礼品申领管理平台，采用前后端分离架构，支持福利活动发布、礼品库管理、员工在线申领、地址管理、发货签收、统计看板、角色权限控制等核心能力。

## 2. 技术栈

| 层级 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 前端框架 | Vue 3 | ^3.5.40 | Composition API |
| 构建工具 | Vite | ^8.2.0 | 快速开发与生产构建 |
| UI 组件库 | Element Plus | ^2.7.6 | 企业级中后台组件 |
| 状态管理 | Pinia | ^2.1.7 | 用户/权限状态 |
| 路由 | Vue Router 4 | ^4.4.0 | 角色路由与守卫 |
| 图表库 | ECharts / vue-echarts | ^5.5.0 | 数据可视化 |
| HTTP 客户端 | Axios | ^1.7.2 | 接口请求封装 |
| 后端框架 | Node.js + Express | - | RESTful API |
| ORM | Sequelize | - | 数据库对象映射 |
| 数据库 | SQLite + better-sqlite3 | - | 轻量级本地文件数据库 |
| 鉴权 | JWT + bcryptjs | - | Token 鉴权与密码哈希 |
| 定时任务 | node-cron | - | 活动状态定时刷新 |
| 导出 | exceljs + fast-csv | - | Excel/CSV 导出 |

## 5. 核心设计

### 5.1 认证与授权

- 登录成功后服务端签发 JWT，Payload 包含 `userId`、`username`、`roleCode`。
- 请求时通过 `Authorization: Bearer <token>` 传递。
- `authJwt` 中间件校验 Token 并注入用户信息。
- `verifyRole` 中间件按角色码放行，`admin` 默认拥有全部权限。

### 5.2 库存防超卖

- 申领提交/修改使用 Sequelize 事务。
- 库存扣减采用条件更新：`UPDATE gift_info SET stock = stock - ? WHERE id = ? AND stock >= ?`。
- 修改申领时先回退旧库存，再扣减新库存。

### 5.3 活动生命周期

- 状态字段：`0 未开始 / 1 进行中 / 2 已结束 / 3 已停用`。
- `node-cron` 每分钟刷新活动状态。
- 员工端接口实时校验时间窗口与状态。

### 5.4 地址快照

- 申领主表冗余保存收货人、电话、完整地址字符串。
- 历史申领单不受后续地址变更影响。

### 5.5 数据导出

- Excel 导出使用 `exceljs`。
- CSV 导出使用 `fast-csv`。
- 通过 `Content-Disposition: attachment` 触发浏览器下载。

## 6. 关键兼容性处理

由于原 `sqlite3` 包在 Node 24 环境下缺少预编译二进制且无法本地编译，本项目采用 `better-sqlite3` 作为底层驱动，并编写了 `utils/sqlite3-wrapper.js` 提供 sqlite3 风格的异步 API，主要解决以下兼容问题：

1. 暴露 `OPEN_READONLY` / `OPEN_READWRITE` / `OPEN_CREATE` 常量。
2. 支持 3 参数构造函数重载。
3. 实现 `serialize` / `parallelize` 方法。
4. 将 Sequelize 生成的 `$1, $2, ...` 占位符转换为 `?`，并按顺序提取参数值。
5. 将 `better-sqlite3` 结果 `{ lastInsertRowid, changes }` 映射为 sqlite3 风格 `{ lastID, changes }`。
6. 对 `all()` / `get()` 遇到非 SELECT 语句时自动降级为 `run()`。
